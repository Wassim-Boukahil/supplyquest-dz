DATABASE FOUNDATION
===================

Create the PostgreSQL + Prisma foundation.

Create only the initial schema for:

organizations
users
roles
user_roles
warehouses
product_categories
products
suppliers
customers

Do NOT add future Phase 1/2 transactional schemas yet.

Use UUID primary keys.

Use created_at and updated_at timestamps.

Use:

* foreign keys
* appropriate unique constraints
* appropriate indexes
* relational integrity

Organization-owned entities must contain organization_id where appropriate.

Use PostgreSQL NUMERIC/DECIMAL types where financial values are introduced.

Do not use floating-point numbers for monetary values.

Use a single PostgreSQL database for V1.

Tenant isolation must be implemented at the application/service layer.

Do not create separate databases or schemas per tenant.

==================================================
MULTI-TENANCY
=============

SupplyQuest DZ is a multi-tenant SaaS.

An organization represents a business/tenant.

Every authenticated user belongs to exactly one organization.

All organization-owned data must be scoped to the authenticated user's organization.

Create reusable middleware/service utilities for accessing:

currentUser
currentOrganization

Tenant isolation must be enforced server-side.

Never rely on frontend filtering for tenant security.

The architecture should make accidental cross-tenant queries difficult.
