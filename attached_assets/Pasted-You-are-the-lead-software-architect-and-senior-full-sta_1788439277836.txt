==================================================
TENANT-SAFE RELATIONSHIPS
==================================================

This is a required Phase 1 improvement.

The existing Product model references category and preferred supplier by ID, but tenant ownership is not independently guaranteed at the database level.

Ensure the application cannot create or use cross-organization relationships.

A user from Organization A must never be able to:

- assign an Organization B category to a product
- assign an Organization B supplier to a product
- place a purchase order against an Organization B supplier
- place a sales order against an Organization B customer
- use an Organization B warehouse
- use an Organization B product
- perform inventory operations using Organization B entities

Enforce this server-side in the service layer.

Where practical, use database-level composite tenant-safe constraints.

Do not rely on frontend filtering.

==================================================
DATABASE TRANSACTIONS
==================================================

Stock-changing workflows must be atomic.

Use Prisma/database transactions where appropriate.

PURCHASE RECEIVING must atomically:

1. validate purchase order
2. validate tenant ownership
3. validate quantities
4. create inventory transaction
5. update inventory level
6. update received quantities
7. update purchase-order status

SALES COMPLETION must atomically:

1. validate order
2. validate tenant ownership
3. validate stock
4. create SALE transaction(s)
5. decrement inventory
6. update order status

WAREHOUSE TRANSFER must atomically:

1. validate source
2. validate destination
3. validate stock
4. create TRANSFER_OUT
5. create TRANSFER_IN
6. update both inventory levels
7. mark transfer completed

If any step fails, none of the changes should persist.
